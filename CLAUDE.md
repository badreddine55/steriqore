## TENANCY (most important decision)
Every tenant-owned table has non-null tenant_id (UUID, FK, indexed); every unique
constraint is scoped (tenant_id, ...). spatie/laravel-multitenancy resolves the current
tenant; a BelongsToTenant trait adds a global scope + auto-fills on create; PostgreSQL
RLS on current_setting('app.tenant_id') is enabled on every tenant table as a second
line of defence. The tenant NEVER comes from a request parameter — only from the
session/token. Any route accepting a client-supplied tenant id is a bug.

## API CONVENTIONS — freeze in S0, they unblock the mobile dev
/api/v1, JSON only, snake_case, ISO-8601 UTC, UUIDv7 ids.
One error shape always:
  {"error":{"code":"CYCLE_NOT_RELEASED","message":"...","details":{},"request_id":"..."}}
Stable machine `code` per business rule; mobile branches on code, never on message.
Status: 200/201, 204, 400, 401, 403, 404, 409 state conflict, 410 recalled/expired,
422, 429, 5xx. Cursor pagination. ETag on read-heavy resources.
IDEMPOTENCY IS MANDATORY on every mutation: client sends Idempotency-Key; server stores
key + request hash + response in Redis 24h and replays it on repeat.
OpenAPI generated by Scramble, committed to docs/openapi.yaml, covered by contract tests
so it can never silently drift.

## INVARIANTS — enforce in DB *and* code, one test each
1. Stock is DERIVED from an append-only stock_movements ledger. No endpoint sets a
   quantity directly. stock_levels is a projection, rebuildable by replay.
2. No label may exist for a cycle that is not released+compliant.
3. A cycle_release row is immutable. Mistakes are corrected by a non_conformity +
   recall, never by UPDATE.
4. A reprint requires a reason, increments print_counter, writes a label_prints row.
5. Scanning a recalled/expired label returns 410 with a blocking code + audit event.
6. Users are soft-disabled, never deleted; past evidence keeps their identity.
7. Evidence tables (cycles, releases, labels, usages, movements, audit_events) have
   NO delete route, and a PostgreSQL trigger raises on UPDATE/DELETE of audit_events.

## LABELS
One label per pouch. Printed: sterilizer id, cycle/load number, sterilization date+time,
use-by date (DLU), operator, sequence in cycle, practice/site. Support QR AND DataMatrix
(French readers expect DataMatrix). The 2D payload is opaque: urn:steriqore:label:<uuid>
or a short URL containing only the label UUID — never patient data, never a secret.
DLU comes from a per-tenant rule table (packaging x storage, EN 868 defaults) and is
frozen onto the label at print time so later rule changes never rewrite past evidence.

## CROSS-CUTTING
Append-only audit_events (actor, tenant, action, subject, old/new values, reason, ip,
request_id). Server-side Policies on every route + an IDOR suite that walks every
resource as a foreign tenant expecting 403/404. Transactions with SELECT ... FOR UPDATE
on stock rows. External API outage must never break the core product. Common screens
< 2s; evidence search < 2s at pilot volume (index deliberately, GIN/tsvector).
Patient data is pseudonymous only; NO real patient data until a written GDPR/HDS
decision exists. Demo/pilot datasets fully synthetic.

## AI RULES (when enabled later)
Suggest-only: autoclave ticket OCR, delivery-note extraction, natural-language search
(emits a constrained filter DTO — never SQL, never raw data), alert digests.
A human confirms before any write; values are source=ai_suggested until confirmed.
No AI output is ever stored as evidence. No patient identifier ever leaves in a prompt.
Every journey must work fully with AI switched off.
